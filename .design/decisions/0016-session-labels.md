# 0016 会话标签

- 状态：已采纳
- 日期：2026-10-23

## 背景

多个 agent 各有一个会话时，调用它们的脚本或 agent 框架需要记住哪个会话对应哪个任务、哪个负责人。tingly-fuse 只知道会话 id，调用方只能自己维护一份 id 到任务的索引，会话被 `drop` 或机器重启后这份索引还要自己对账。编排不归 tingly-fuse（[0004](0004-environment-prep-out-of-scope.md) 的边界不变），但让调用方不必另存索引是文件层该提供的。

## 决定

- 每个会话有一组自由的键值标签，存在 `session.json` 的 `labels` 里，tingly-fuse 不解释它们。
- **创建时设置**：`spawn --label k=v`、`git worktree add --label k=v`（可重复，也可逗号分隔）。**之后修改**：`label <session> k=v ... k-`，`k-` 删除一个键，不带参数打印。
- **按标签查找**：`list -l k=v`（值相等）、`list -l k`（键存在），可重复，全部满足才列出。输出新增 LABELS 列。Go API：`SpawnOptions.Labels`、`WorktreeOptions.Labels`、`Manager.SetLabels`、`Manager.SessionsWithLabels`。
- **键**：最多 63 字节，字母数字开头，其后是字母、数字、`.`、`_`、`-`、`/`（`example.com/owner` 这样带前缀的键可以用）。**值**：最多 256 字节，不含控制字符。不合法在创建会话之前就报错，不会留下半个会话。
- **并发**：修改在会话目录里的锁（flock）下读改写，两个同时的 `label` 不会互相覆盖。创建时设置不需要锁，会话此时还没人能看见。

## 理由

- 调用方不用另存索引，会话列表本身就是事实来源，`drop` 之后标签自然消失。
- 只做键值和等值、存在两种选择器，够用且容易说清。区间、集合、取反等 Kubernetes 式选择器目前没有需要，真需要时再加。
- 不解释标签，意味着 tingly-fuse 不会因为某个标签改变行为，边界不动。

## 被放弃的选项

- **由 tingly-fuse 内置任务或负责人字段。** 这是编排的概念，不同框架叫法不同。
- **在会话外另存标签索引。** 又多一份要和会话对账的状态。
- **标签随 `exec` 注入环境变量。** 目前没有需要，而且会让标签变成行为的一部分；调用方想要可以自己在命令里带。

## 后果

- 已有会话没有标签，不需要迁移（字段省略即为空）。
- 标签只记在会话元数据里，不进 git，也不随 push 带走。
