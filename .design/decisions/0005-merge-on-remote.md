# 0005 合并交给远端，会话只产出分支

- 状态：已采纳
- 日期：2026-10-17

## 背景

多个 agent 各自在自己的视图里改同一个仓库，最终需要汇合。

## 决定

每个会话从某个 commit 出发，只在自己的分支（默认 `agent/<id>`）上堆叠提交，通过 `push` 推到真实的 upstream。合并、评审、冲突处理都发生在远端（PR 或 MR），tingly-fuse 不在本地做合并。

本仓库自己的改动也同样走分支加 PR 合并。

## 理由

- 和 Google CitC、Meta EdenFS 的模型一致：本地只是视图加改动，合并交给评审系统。
- 存储层只需要管读写分层，复杂度低很多。

## 后果

- 基础 checkout 的 origin 指向真实 upstream，不是本地镜像，否则 push 会落到镜像里。
- 跨会话冲突只能在推送之后发现。调研里设想过的路径级重叠预警，在本地合并之外仍然可做，但目前不在范围内。
